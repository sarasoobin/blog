## 🗓️ 2026-07-27 추가 — API 연동 준비 (배포 · API 기초 · 주소→좌표)

### 33. 배포 = "내 컴퓨터 밖에서도 돌게 만드는 것"

`localhost`는 **"이 컴퓨터"** 라는 뜻이라 그 주소는 남에게 안 열린다. 배포는 그걸 인터넷에 올려 아무나 접속하게 만드는 것.

| | 프론트엔드 | 백엔드 |
| --- | --- | --- |
| 결과물 | **파일**(`dist/` = HTML·CSS·JS) | **계속 켜져 있는 프로그램** + DB |
| 배포한다 = | 파일을 서버에 갖다 놓기 (전단지 붙이기) | 컴퓨터 한 대를 24시간 돌리기 (주방에 요리사 상주) |
| 팝잇 | Vercel · `popit.co.kr` | nginx + Spring · `api.popit.co.kr` |

프론트는 **git push → Vercel이 자동 감지 → `pnpm build` → 배포**(CI/CD). 아무도 파일을 손으로 안 올린다.

⚠️ 그래서 **`pnpm build`가 로컬에서 실패하면 배포도 실패**한다. `build = tsc -b && vite build`라 **타입 에러 하나로 배포가 멈춘다.** (`pnpm dev`는 타입 에러가 있어도 화면이 뜨므로 방심 금물) → PR 전에 `pnpm build` 한 번.

### 34. 도메인 분리 + SPA rewrite가 만든 404 함정

이름 하나(`popit.co.kr`)는 한 곳만 가리킬 수 있다 → 백엔드는 `api.`를 붙여 분리한다.

`vercel.json`의 `{"source": "/(.*)", "destination": "/index.html"}` = **어떤 경로로 들어와도 React 앱을 보여줘라**(SPA에 필수. 새로고침해도 안 깨지게). 그래서 `popit.co.kr/swagger-ui/...`로 들어가면 백엔드가 아니라 **우리 앱**이 뜨고, 그런 라우트가 없으니 React Router가 404를 낸다.

⚠️ **`💿 Hey developer 👋 ... errorElement` 에러 = React Router 기본 화면 = 백엔드가 아니라 내 앱이 낸 에러.** 에러 화면의 "생김새"로 어느 쪽 문제인지 판별할 수 있다.

### 35. API 요청의 4요소 + 상태코드

API 요청 = 편지 부치기.

| 편지 | API | 예 |
| --- | --- | --- |
| 어디로 | **URL** | `https://api.popit.co.kr/api/v1/spaces` |
| 뭘 하려고 | **메서드** | `GET` 조회 / `POST` 생성 / `PATCH` 수정 / `DELETE` 삭제 |
| 내용물 | **Body** | `{ "buildingName": "...", ... }` (JSON) |
| 내가 누군지 | **Header** | `Authorization: Bearer <토큰>` |

`POST /api/v1/spaces` 처럼 **앞이 메서드, 뒤가 주소**. `{spaceId}` 는 실제 값을 끼워 넣으라는 뜻(`/api/v1/spaces/12`).

**상태코드** — `200` 성공 / `400` 보낸 데이터가 이상함 / `401` 로그인 안 됨 / `403` 권한 없음 / `404` 그런 주소 없음 / `500` 서버가 터짐.

⭐ **400번대 = 내(프론트) 잘못, 500번대 = 백엔드 잘못.** 이 구분만 해도 삽질 시간이 확 준다.

### 36. 응답의 "봉투" — 진짜 데이터는 `result` 안

팝잇 백엔드는 모든 응답을 공통 형식으로 감싼다.

```json
{ "isSuccess": true, "code": "FACILITY200_1", "message": "...", "result": { ...진짜 데이터... } }
```

겉의 3개는 포장지. **쓸 값은 `result` 안에 있다.** 모르면 "데이터가 왜 안 나오지?"로 헤맨다.

### 38. 환경변수 `.env`

API 키처럼 **코드에 박으면 안 되는 값**을 빼두는 파일. 코드는 GitHub에 올라가니까 키를 박으면 전 세계에 공개된다 → `.gitignore`로 막는다(`.gitignore:27`). **그래서 팀원 각자 자기 컴퓨터에 만들어야 한다**(깃으로 안 내려옴).

```
VITE_KAKAO_JS_KEY=값        ✅
VITE_KAKAO_JS_KEY = "값"    ❌ 따옴표·띄어쓰기 X
```

- **`VITE_` 접두사 필수** — Vite는 그 접두사가 붙은 것만 코드로 넘겨준다. 없으면 `undefined`.
- ⚠️ **`.env`는 서버 시작 시 딱 한 번 읽는다** → 값을 바꾸면 `Ctrl+C` 후 `pnpm dev` **재시작 필수.** (30번 항목과 같은 계열의 함정)
- `VITE_`가 붙은 값은 **브라우저에 그대로 노출**된다. 카카오 JS 키는 원래 공개용(도메인 제한으로 보호)이라 괜찮지만, 진짜 비밀 키는 절대 프론트에 두면 안 된다.

### 39. 브랜치 뜨기 전에 반드시 `git pull`

```bash
git switch dev                              # 1. 항상 어디 서 있는지 확인
git pull                                    # 2. 최신 받기 ← 빼먹으면 안 됨
git switch -c feat/85-address-geocoding     # 3. -c = create (복사본 만들며 이동)
```

브랜치 = **원본(dev)을 건드리지 않는 작업용 복사본.** `git status`의 **`behind 3`** = "GitHub의 dev보다 내 dev가 3커밋 뒤처짐". 그 상태로 브랜치를 뜨면 **낡은 코드 위에서 작업**하게 되어 빌드가 깨져 있거나 나중에 충돌이 난다.

브랜치명은 `feat/이슈번호-기능명` (`feat/85-address-geocoding`).

⚠️ `CLAUDE.md` · `docs/` · `.omc/` 는 **gitignore가 안 돼 있다** → `git add .` 하면 개인 노트가 팀 레포에 올라간다. **파일을 콕 집어서 `git add`** 할 것.

### 40. `number | null` — "없음"을 `0`으로 표현하면 안 된다

폼 필드가 대부분 `string`인 이유는 **`<input>`에 사람이 친 값은 무조건 글자**라서. 반면 좌표는 사람이 안 치고 SDK가 계산해주며 백엔드도 `number`를 요구 → `number`.

"아직 값 없음"을 표현할 때:

| 후보 | 판정 |
| --- | --- |
| `""` | ❌ 타입이 `number`인데 글자를 못 넣음 |
| `0` | ❌ **0도 지구상의 진짜 좌표** — "없음"과 구분 불가 |
| `null` | ✅ "값이 없다" 전용 표현 |

`|`는 **"또는"**(유니온). `number | null` = 숫자이거나, 아직 없거나.

### 41. ⭐ 타입검사 통과 ≠ 백엔드와 이름이 맞음

`longitude`를 `logitude`로 잘못 쳤는데 **`tsc` 통과.** interface와 초기값 **둘 다 똑같이 틀렸으니 TS 입장에선 일치**하기 때문.

```
설계도: logitude / 실물: logitude  → 일치! 통과 ✅   (백엔드가 뭘 원하는지 TS는 모름)
```

그대로 뒀다면 며칠 뒤 `POST /spaces`에서 **`longitude` 누락 → 400**이 나고, "좌표 넣었는데 왜?"로 1시간 삽질했을 것.

⭐ **백엔드로 보내는 필드 이름은 명세에서 복사-붙여넣기.** 손으로 치면 오타가 난다.
💡 VS Code **F2**(이름 바꾸기)를 쓰면 관련된 곳이 한 번에 바뀐다 — 한 군데만 고치고 까먹는 사고 방지. (27번 "정적검사 통과 ≠ 로직 맞음"의 확장판: 이번엔 **외부 시스템과의 약속**이 어긋난 경우)

### 42. ⭐ 비동기 — 콜백 → Promise → `await`

지금까지 쓴 코드는 전부 **즉시 답이 나오는** 것들이었다(`form.address !== ""`). 서버·SDK에 물어보는 일은 **시간이 걸려서** 그렇게 못 쓴다.

```ts
const 좌표 = geocoder.addressSearch("서울...");   // ❌ 안 됨
geocoder.addressSearch("서울...", (result) => {}); // ✅ "답 오면 이거 실행해줘"
```

☕ **카페 비유**: 주문하자마자 커피가 나오지 않는다. **진동벨**을 받고 앉아 있다가 울리면 가지러 간다. 저 화살표 함수가 **진동벨(콜백)**.

**Promise** = 그 진동벨의 **표준 규격**. `await` = "될 때까지 여기서 기다려" → 즉시 값이 나오는 것처럼 읽힌다.

```ts
export const geocodeAddress = (address: string): Promise<Coordinate | null> =>
  new Promise((resolve) => {            // "약속서 발행"
    ...
    resolve(값);                         // "다 됐어, 이게 결과야" 버튼
  });

const coord = await geocodeAddress(address);   // 쓰는 쪽은 한 줄
```

`Promise<T>` = "지금은 없지만 나중에 `T`가 옵니다"(커피 교환권). ⚠️ 실패 분기에서 `resolve(null); return;` — **`return`을 빼먹으면** 아래 `resolve`까지 실행되어 의도가 안 드러나는 코드가 된다.

💡 `axios`도 전부 Promise다. 여기서 익히면 API 연동 때 그대로 쓴다.

### 43. 카카오 Geocoder 함정 3개

주소(글자) → 좌표(숫자) 변환기. `new window.kakao.maps.services.Geocoder()`.

1. ⚠️ **x = 경도(longitude), y = 위도(latitude)** — 우리는 "위경도"라 위도부터 말하지만 카카오는 반대. **지도를 좌표평면으로 생각**하면 된다(x=가로=동서=경도, y=세로=남북=위도). 뒤바꾸면 서울 공간이 **태평양 한가운데** 찍힌다.
2. ⚠️ **값이 `string`으로 온다** (`"37.5006"`) → `Number()`로 변환해야 store·백엔드의 `number`와 맞는다.
3. ⚠️ **못 찾을 수 있다** — `status`가 `OK` / `ZERO_RESULT` / `ERROR`. **`OK`이면서 `result[0]`도 있을 때만** 좌표를 쓴다. 안 그러면 `result[0].y`에서 앱이 터진다.

SDK 로드는 `useKakaoLoader()`가 담당하며 `libraries=services`가 이미 포함돼 있다(`useKakaoLoader.ts:44`) → **Geocoder는 추가 설치 불필요.** 타입 선언도 `types/kakao-maps.d.ts`에 이미 있음.
